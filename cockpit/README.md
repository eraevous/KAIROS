# cockpit/: building the Kairos Cockpit

Scripts only. The Cockpit itself is generated by [relay-kit](https://github.com/eraevous/relay-kit)
(`relay-kit cockpit`, contract `relay-kit/cockpit@3`) from the private coordination records, and its
output is **never committed here**: it holds the records' text. Keep it on your machine, or serve it
only behind authentication.

| File | What it does |
| --- | --- |
| `build.sh` / `build.ps1` | 1. `relay-kit prs` reads the pull requests of the repositories in `repos.txt` into the records (`governance/pr-state.jsonl`, append-only). 2. `theme_from_tokens.py` turns the records' design tokens into a Cockpit theme. 3. `relay-kit cockpit --brand Kairos --theme … --landing prs` writes the page, opening on Pull requests. |
| `theme_from_tokens.py` | Maps the design tokens (identity, status, surface, type; dark and light) onto the Cockpit's colour variables. `--mark amber` or `--mark blue` picks the colour that carries the Kairos name, which is still an open design question. |
| `repos.txt` | The repositories whose pull requests are shown. |

```
RECORDS=~/src/relay-kit-private ./cockpit/build.sh --mark amber        # or --mark blue; --no-fetch to skip GitHub
$env:RECORDS="C:\src\relay-kit-private"; .\cockpit\build.ps1 -Mark blue
```

The page fetches nothing and writes nothing; only `relay-kit prs` reaches GitHub, at build time,
as the account `gh` (or `GITHUB_TOKEN`) is signed in as. PR text shown is each PR body's own
`## What / ## Why / ## How / ## Authorized`, with an `Author:` line naming who wrote it; nothing is
summarised. Fonts (Fraunces, Source Sans 3) are named, not bundled: without them installed the page
falls back to Georgia and the system sans.
